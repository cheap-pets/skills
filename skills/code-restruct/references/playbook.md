# 信号识别、处置手段与执行次序（S1–S8）

配套 `SKILL.md` 步骤 1–3。本文件为通用信号阈值、识别标准、完成判据、处置手段与执行次序的**单点定义处**；各语言分册 `references/lang-<stack>.md` 允许按语言生态复述特化口径、扫描命令与豁免项。

排序时结合近 6 个月 Git 改动频次（热点乘数），优先处理高频改动的痛点文件：
```bash
git log --since="6 months ago" --name-only --pretty=format: -- <模块路径> | sed '/^$/d' | sort | uniq -c | sort -rn | head -30
```

## 1. 核心阈值表（通用单点定义）

阈值是校准默认值，有实测证据可调。

| 阈值项 | 默认标准 | 设定依据与豁免说明 |
| :--- | :--- | :--- |
| **单文件行数（S7）** | **硬线 >600 行** / **软线 400–600 行** / **新拆出文件目标 ≤350 行** | `>600` 行直接引发 Agent 上下文注意力衰减与行号定位漂移，单指标无条件入围；`400–600` 行仅在伴随“多职责 + 近 6 个月高频改动”时入围。**豁免**：纯 schema/静态配置表/单一状态机登记豁免不拆；生成代码、`*.d.ts`、`*.g.cs`、`*.Designer.cs`、迁移文件不计；`.vue` 看整文件 `>600` 行或 `<script>` `>400` 行；`.rs` 剔除底部 `#[cfg(test)] mod tests` 行数 |
| **位置参数收敛（S8）** | `>5` 个位置参数；或 `≥3` 个且含高危形态 | 调用点超过 5 个位置参数，或 `≥3` 个参数但含布尔旗标、同类型相邻参数、`undefined`/`None`/`null` 占位、或连续透传 `≥2` 层时，Agent 与人类目检极易错位 |
| **同源重复判定（S4）** | 双证据任一 | ① 注释自认同源（`keep in sync` / `同源` / `保持一致`）；② `≥2` 处核心业务规则 AST 归一化后逐节点相等（无 AST 工具时降级为去空白逐 token 相等）。仅“看起来像”不提取，容忍无演进耦合的局部显式样板 |

## 2. S1–S8 信号全表（按优先级排序）

| 优先级 | 信号 | 识别方法 | 处置手段与前置条件 | 完成判据 |
| :--- | :--- | :--- | :--- | :--- |
| **P0** | **S7 多职责文件/目录** | 单文件 **>600 行（硬线）**；或 **400–600 行（软线）** 且伴随多职责（文件内含互不消费的独立职责组）与近期高频修改 | **手段**：按业务域拆分为独立文件/类/Composable（先走 **T2a** 外提纯函数/常量/类型，再走 **T2b** 抽离含状态子模块）。<br>**前置条件**：目标文件自身不在 S5 环依赖内（未跑全模块 S5 工具时，先用反向 `import`/`use` grep 做目标文件局部环检查）；新拆出模块必须通过**浅模块删除测试**（若删掉该模块后调用方复杂度未变，仅为透传拼装，则不拆）；严禁按行号机械截断为 `part1/part2` | **>600 行非豁免文件清零**（或已记入不做清单并经用户确认）；400–600 行文件无多职责混杂；新拆出文件目标 `≤350` 行；按功能关键词 grep 文件名或导出名可直接命中 |
| **P0** | **S5 跨层与环依赖** | 按分层模型查下层→上层反向引用边、模块间环依赖（含 Python 函数内延迟 `import` 掩盖的真实环）。第三方工具不可用时，默认用反向 `import`/`use`/`using` grep + 目录分层人工核对降级执行 | **手段**：将跨层共享的纯函数/无状态基础类型独立成模块（**T2a**）。<br>**前置条件**：共享原语无层内状态耦合；**因解环会改变模块加载顺序，动手前必须先静态确认环内模块无顶层副作用（有则按 R4 触点处理）** | 无下层→上层反向引用边、无环依赖；项目既有依赖检查工具（如 `dependency-cruiser` / `import-linter` / `cargo modules`）扫描通过；**无工具/无配置时**以反向 `import`/`use` `grep` + 目录分层人工核对替代，判据接受该结果（汇总标注核对方式） |
| **P1** | **S6 跨文件命名消歧** | **不扫 1–3 字符局部短变量**。聚焦**跨文件导出符号、Store/Context 字段、组件 Props/Emit、参数袋键名**中的同名异义或因冲突被迫起别名（`as` / `using Alias =`）的标识符 | **手段**：对齐项目既有领域术语消歧改名（**T1**）；`ast-grep` 或 LSP 可用时优先选用该工具批量改写。<br>**前置条件**：新名不与既有符号冲突；若触及跨边界字符串契约（模板、序列化键、反射，见 R4 触点 3），同步核对契约或移入不做清单 | 命中的跨文件非豁免标识符在模块内语义唯一，无新增冲突别名 |
| **P1** | **S4 耦合性同源重复** | 双证据任一：① 注释自认同源；② `≥2` 处核心业务函数 AST 归一化后逐节点相等 | **手段**：合并为单一事实源，调用点改为引用（**T3**）。<br>**前置条件**：有明确的等价性校验点（注释自认约束或既有调用契约）；**严禁为合并略有差异的代码而引入大量布尔参数或条件分支** | 归一化比对无耦合性重复组；自认同源的注释清零或已指向同一定义 |
| **P2** | **S8 参数形态（机会性）** | **接触即改，不单设批次**（除非已引发缺陷）。触发：位置参数 `>5`；或 `≥3` 且含布尔旗标 / 同类型相邻参数 / `undefined`(`None`/`null`) 占位；或同一组参数连续透传 `≥2` 层 | **手段**：转为强类型 Options/Params 对象或关键字参数（**T4**），调用点同批修改。<br>**前置与豁免**：改动前先 `grep` 非直接调用引用（防 `arr.map(fn)`、`.bind`、事件回调等当值传递静默错位）；满足下述 **§3 S8 豁免条件** 的一律不改 | 接触到的非豁免超标函数已转为强类型参数对象或关键字参数，调用点自解释 |
| **P2** | **S1 内部纯转口** | **按需清理**：针对**引发 S5 环依赖**、**二跳以上嵌套转发**的内部聚合文件（符号引自另一实现文件，本文件无定义或门控包装），以及 **Python 未声明 `__all__` 的通配转口（`from .x import *`）** | **手段**：删内部冗余转口，消费方直接引用实现文件（**T1**）；`ast-grep` 或 LSP 可用时优先选用。<br>**前置条件**：已核实为纯转发；**保留语言生态标准公共入口**（如 `package.json` 的 `main`/`exports` 根 `index`、Python 包根 `__init__.py` 的 `__all__`、Rust `lib.rs` 顶层 `pub use`），并在计划或收尾汇总中登记 | 引发环依赖、二跳以上或 Python 未声明 `__all__` 的通配纯转口清零；公共入口保持冻结 |
| **登记项** | **S2/S3 隐式注入与状态** | 参数袋/DI/事件总线/宏跨文件隐式调用（S2）；单对象 `>20` 字段跨多文件写入或全局可变状态（S3） | **手段**：**不单设批次，不加 `@reads/@writes` 自定义注解，不写手写审计脚本**。命中时在计划中登记一行“已知隐式边”；在拆文件（S7）或理依赖（S5）顺带接触时，尽量改为显式参数或将状态写入收敛至 Store Action / 类方法 | 已知隐式边已在计划或收尾汇总中登记；顺带收敛处无遗漏引用 |

## 3. S8 参数形态专项细则与豁免清单

**豁免条件（命中任一则不改）**：
1. **框架或组件库规定的回调签名**：如前端组件库（MUSSEL 等）的 `formatter` / `validator` 回调、组件 `emit` 签名、`Array.prototype.map/reduce` 等高阶函数回调；Python 的 Web 路由处理函数、Pytest fixture、信号 `receiver`。
2. **上游契约锁定的方法**：接口实现（Interface implementation）、抽象类/基类方法重写（`override`）、Rust `trait` 实现方法（签名由上游 trait/interface 决定，不可单方修改）。
3. **被包外消费的公共导出函数**：走公共 API 冻结核对，不改对外签名。
4. **S2 参数袋对象**：不在 S8 中拆分。

**各栈执行注意**：
- **Vue / React Composable（JS/TS）**：Options 对象内涉及响应式数据时，必须传入 `Ref` 或 getter（`() => val`，内部配合 `toValue`），**严禁在调用点解构 `reactive` 对象后传值**，否则会静默丢失响应性。
- **Python**：优先使用 `*,` 转为 Keyword-Only 参数，或收敛为 `@dataclass(frozen=True)` / `TypedDict` / `Pydantic BaseModel`；**严禁退化为无类型 `dict` 或 `**kwargs`**（否则制造新的 S2 隐式依赖）。
- **C# / Rust**：C# 普通方法封装为 `record` 或 Parameter Class（构造函数注入参数 `>5` 视为类职责过重，关联 S7 拆分而非打包参数）；Rust 收敛为 typed Config/Params `struct`（配合 `Default` 或 Builder）。

## 4. 执行次序

1. **S7 直通解锁**：只要目标大文件自身不在 S5 环依赖中（工具未安装时通过局部反向 `import`/`use` grep 核实），即可直接开始拆分，无需等待全模块 S1/S2/S3 清理完毕。若目标文件处于 S5 环依赖内，先执行 S5 解环（T2a），再执行 S7 拆分。
2. **单文件拆分内部次序（先 T2a 后 T2b）**：
   - 第一刀优先执行 **T2a（纯搬移）**：将顶层纯函数、静态配置/常量、纯类型定义（`interface` / `type` / `struct` / `dataclass`）抽离至独立文件。T2a 无状态、免探针基线、验证极快。
   - 第二刀再评估剩余代码：若仍超标且包含多个独立状态域，再执行 **T2b（状态/Composable/子服务拆分）**。
3. **机械改写批次隔离**：全仓或跨多文件的 S1（删转口）与 S6（重命名）属于机械引用改写（T1），应单独成批提交，不与 S7 的文件拆分混在同一 commit 中，保持 `git diff` 干净易审。
4. **S8 随手收敛**：在执行 S7/S5/S4 接触到具体函数与调用点时顺带完成 S8 参数收敛，不开专项批次。

## 5. 不做清单分类标准（配套 R5）

任何扫描命中的问题若决定不处理，须按以下 4 类理由登记（≤5 文件在对话说明，>5 文件记入 `restruct-plan.md`），并附重评触发条件：

| 理由类型 | 判定准则 | 典型示例 |
| :--- | :--- | :--- |
| **收益成本倒挂** | 根治需架构换血，超出“行为不变的结构重构”边界；或文件虽在 400–600 行区间但近半年零改动、单一职责且无耦合痛点 | S2/S3 历史遗留全局事件总线仅登记不重造；500 行但长期稳定且职责单一的算法模块不拆 |
| **收益为零或负** | 改名或搬移违背语言生态惯例，或强拆高内聚文件反而导致跨文件高频横跳、产生透传浅模块 | Python `__init__.py` 或 Rust `lib.rs` 公共 facade 不删；`>600` 行的纯 Schema/静态映射表/单一状态机豁免不拆 |
| **触及行为变更** | 验证时发现必须修改既有测试断言或输出基线才能通过（按 R4 立即回滚） | 删转口或拆模块触发顶层副作用时序变化导致测试失败，回滚后移入不做清单交用户另开分支处理 |
| **当批风险不可控** | 目标代码落在未提交改动区且无法行级避让，或缺乏测试且涉及高危动态反射/宏展开 | 移入后续独立批次，待在途改动提交或补齐特征测试后重评 |
