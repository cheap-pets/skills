# 结构重构（行为不变）

仅由用户手动调用：`/code-restruct <模块路径>`。未给模块路径时，先问一句目标模块。

## 1. 目标与原则

核心目标是**提升 Coding Agent 读取、分析、修改代码的效率**，其次兼顾人类低成本审查，不追求主观“代码美观”。排序、取舍、验收统一用一条判据：

> **agent 只用静态手段，能否回答：① 这个功能在哪？② 改这里影响谁？**

围绕 Agent 工作特性，遵循三条原则：

1. **读取效率（上下文局部性）**：单次需求涉及的核心逻辑应集中在 1–3 个高内聚文件。既要拆分 `>600` 行的巨型文件，也要**严防过度碎裂**（将 450 行高内聚逻辑拆成多个碎片文件会迫使 Agent 跨文件高频跳转）。
2. **分析效率（签名即契约 & 工具感知选型）**：跨文件导出与调用须具备显式类型签名，使 Agent 读签名即可安全调用。**工具感知选型**：默认静态手段为模块导入图、函数/类型签名、`grep`、`wc -l`；当环境中 `ast-grep` 或 LSP 实际可用时，在步骤 1 末尾登记，执行 S1（删转口）与 S6（同名消歧）批量改写时优先选用该工具（不改变信号 P 级与批次归属）。
3. **修改效率（单向依赖 & 纯/状态分离）**：优先消除环依赖与跨层反向依赖（S5）；拆分大文件时先剥离无副作用的纯函数、常量、类型（T2a），将有状态逻辑控制在最小范围。

**适用边界**：行为不变的依赖梳理、文件/目录拆分、跨文件重命名、冗余转口清理、同源重复合并、参数收敛。**不适用**：新功能开发、改变行为的重写、性能优化、纯格式化。

**语言栈路由**：开始步骤 1 前，必须按目标模块语言只读取对应的 1 份 `references/lang-<stack>.md`（`js` / `python` / `csharp` / `rust`，其中 `lang-js.md` 同时适用于 JS/TS/Vue）。目标语言不在四者之列时，先向用户说明并确认参照的分册。

## 2. 显式引用图与真实依赖图

静态模块导入语句（`import` / `using` / `use`）可能因以下因素偏离真实依赖：

- **主动治理项**：**S5 跨层反向依赖与环依赖**（导致影响面横跳）、**S1 嵌套或致环转口**（多层转发遮蔽实现）。
- **登记并顺带收敛项**：**S2 运行时注入/隐式分发**（参数袋、DI 动态解析、事件总线、宏展开）与 **S3 隐式共享可变状态**（超大可变上下文或全局状态）。S2/S3 不单设批次、不发明自定义注释 DSL；命中时在计划中登记一行“已知隐式边”，在执行 S7/S5 顺带接触时优先改为显式参数或收敛至 Store Action/方法。

## 3. 信号速查与改动类型

### 改动类型（决定验证组合与批次容量）

- **T1 归一**：仅修改导入/引用行、标识符、注释；无新文件、无新逻辑。
- **T2a 纯搬移**：新文件 + 源文件删除块（引用改写可有可无），搬移内容不改逻辑。对象：顶层纯函数、常量、类型定义（无闭包状态、无生命周期/DI 副作用、无顶层副作用）；C# `partial class` 按成员块拆文件同属此类。
- **T2b 状态拆分**：抽离含响应式状态、生命周期钩子、类实例状态或 DI 注册的子模块/服务。
- **T3 重复提取**：≥2 处同源实现合并为单一事实源 + 调用点改引。
- **T4 参数收敛**：函数/方法签名与调用点参数列表同步变化。

> 混批时整批按最高要求类型验证。

### 信号速查表（S1–S8）

通用行数阈值、详细识别方法、完成判据、前置条件与执行次序单点定义于 `references/playbook.md`（各语言分册仅复述生态特化口径）。

| 优先级 | 信号 | 一句话识别 | 处置手段 | 类型 |
| :--- | :--- | :--- | :--- | :--- |
| **P0** | **S7 多职责大文件** | 单文件超硬线，或超软线且伴随多职责 + 近期高频修改 | 先外提纯函数/常量/类型（T2a），再按域拆有状态子模块（T2b）；须过浅模块删除测试 | T2a / T2b |
| **P0** | **S5 跨层与环依赖** | 下层→上层反向引用、模块环依赖 | 共享纯函数/基础类型独立成模块（须先静态确认环内无顶层副作用） | T2a |
| **P1** | **S6 跨文件命名消歧** | 跨文件导出符号、Store/Context 字段、Props/Emit、参数袋键名同形异义或冲突别名 | 对齐领域术语，用 LSP Rename 或 `ast-grep` 批量消歧改名 | T1 |
| **P1** | **S4 耦合性同源重复** | 注释自认同源，或 ≥2 处核心业务规则 AST 归一化后完全相等 | 合并为单一事实源（容忍无演进耦合的局部样板，禁止过度抽象） | T3 |
| **P2** | **S8 参数形态（机会性）** | 接触即改，不单设批次：位置参数过多、含布尔旗标/同类型相邻/空值占位或连续透传 | 转为强类型 Options/Params 对象或关键字参数 | T4 |
| **P2** | **S1 内部纯转口** | 引发 S5 环依赖、二跳以上嵌套转发或 Python 未声明 `__all__` 的通配转口 | 删内部冗余转口，消费方直引实现文件；保留包根标准公共入口 | T1 |
| **登记** | **S2/S3 隐式注入与状态** | 参数袋/DI/事件隐式调用（S2），或跨文件超大可变状态（S3） | 登记为“已知隐式边”；在 S7/S5 接触时顺带收敛为显式参数或 Action | — |

## 4. 四步工作流

仅设 **执行 Agent** 与 **用户** 两个角色，不拆虚拟角色，不强制开启子 Agent 做设计核验。

### 步骤 1　快速诊断与早退门禁

1. 读取 `references/playbook.md` 与对应语言的 `references/lang-<stack>.md`。
2. 并行执行扫描命令：
   - **大文件扫描**（见语言分册 S7 命令，`<模块路径>` 传仓库相对目录）。
   - **近 6 个月 Git 改动频次**（热点乘数，命令见 `playbook.md`）。
   - **环依赖与跨层反向依赖扫描（S5）**：优先运行语言分册 S5 工具；**工具未安装或不可用时，默认执行降级核对**（运行分册 S5 的反向 `import`/`use`/`using` grep + 目录分层人工核对，核对通过即计入“S5 已检查”）；确实无法核对时才标注“S5 未检查”。
   - **S4 自认同源注释扫描**（执行对应语言分册 S4 带 `--include` 过滤的扫描命令）。
3. 一句话登记当前可用静态手段（grep / `ast-grep` / LSP）。
4. **早退门禁**：若**无超硬线且非豁免的大文件**（豁免口径见 `playbook.md` 阈值表）、**S5 已检查且无命中**，且软线区间文件均为低频稳定或单一职责 → 输出“未发现 P0 级问题”，**询问用户是否继续排查 P1（S4 / S6）**，不生成任何文档。若 S5 确无法核对而处于“未检查”状态，输出“未发现大文件 P0（S5 未检查）”并交用户裁决是否继续。

### 步骤 2　轻量规划与确认

- **小规模（预计改动 ≤5 个文件）**：**零中间文档**，直接在对话中列出：`[目标文件] 命中信号 → 手段（类型）→ 验证命令` 及不做项，经用户确认后进入步骤 3。
- **中大规模（预计改动 >5 个文件或跨多批次）**：仅生成单份 `docs/restruct/<模块>/restruct-plan.md`（项目有约定目录时从其约定），包含：
  1. 模块依赖简图（直接粘贴工具输出或分层列表，不手写长文）。
  2. 批次计划表：`批号 | 目标文件 | 信号 | 手段 | 类型 | 状态`（`状态` 列支持跨会话续作）。
  3. 不做清单（理由类型 + 重评触发条件）、保留的公共入口登记、已知隐式边登记（S2/S3 命中项，一行一条）。
  - **注**：设计期不写消费方全量清单与行号快照，留到步骤 3 每批动手前实时查询。规划经用户确认后进入步骤 3。

### 步骤 3　分批执行与即时验证

- **执行次序**：目标文件自身不在 S5 环内即可直接执行 S7 拆分（若未跑全模块 S5 工具，拆前先用反向 `import`/`use` grep 做目标文件局部环检查；无需等待全模块 S1/S2/S3 清零）。单文件内部先做 **T2a**，再做 **T2b**；接触到的 **S8** 顺带收敛；S1 / S6 的全仓机械改写单独成批。
- **批前检查**：
  1. 实时 `grep` / LSP 查询本批文件、消费方与最新行号。
  2. 检查 `git status`：有未提交改动时优先请用户提交/暂存，其次行级避让（只改引用与命名行），避让不了则推迟该区域。
  3. 记录起点 HEAD 的编译/Lint 告警基线（改后以“不新增告警”为通过标准）。
- **验证与提交**：每批改完在当前上下文按 §5 验证矩阵运行命令；通过后提交 commit，**将审查摘要直接写入 commit message 正文**（T2b/T3 批的验证命令与退出码一并记入）。

### 步骤 4　收尾

- 执行全模块 build + 类型检查 + 既有测试 + 残留引用扫描。
- 输出简明变更汇总（含已完成批次、保留的公共入口、不做清单、未检查项）。中大规模重构可在用户要求时选做一次“两问抽测”（取 3 个功能点与 3 个改动点验证静态定位准确性）。

## 5. 验证矩阵（默认去探针化）

- **告警基线口径**：在起点 HEAD 记录 build / lint / 类型检查告警数，改后**零错误且不新增告警**即通过，不要求清零历史遗留告警。
- **“无自动化测试覆盖”判定口径**：在测试目录中 `grep` 不到对本批目标文件/导出符号的 `import` 或直接调用，即判定为无自动化测试覆盖；无法确认时一律按无覆盖处理。

| 类型 | 默认充分验证组合（零探针成本） | 探针基线触发条件（仅满足时读取 `references/verification.md` 采集） |
| :--- | :--- | :--- |
| **T1** | build / 类型检查（Vue 项目含 `vue-tsc --noEmit`）+ 既有测试 + 残留引用扫描 + `git diff` 核对；涉及包外导出加 **API 冻结核对** | 命中 R4 触点，**且**该路径无自动化测试覆盖（类型检查不覆盖字符串契约，不能替代测试豁免） |
| **T2a** | build / 类型检查 + 既有测试 + 残留扫描 + `git diff --color-moved` + 行数与浅模块核对；涉及包外导出加 API 冻结核对 | **无 R4 触点时免探针基线**。S5 批须先静态确认环内模块无顶层副作用；有触点则按触点处理 |
| **T2b** | build / 类型检查 + 既有测试 + 残留扫描 + 状态与生命周期注册顺序核对 | 目标路径无自动化测试覆盖：采单次探针基线，或经用户确认以 Agent 生成的“人工冒烟清单”替代 |
| **T3** | build / 类型检查 + 既有测试 + 残留扫描 + 同源约束等价性逐条核对 | 目标路径无自动化测试覆盖 |
| **T4** | 强类型：类型检查（含模板检查）+ 既有测试 + 调用点 diff 配对 + API 冻结核对；弱类型：加调用点逐参数位核对 | 函数被当值传递（如 `arr.map(fn)`、`@evt="fn"`、`.bind`、动态回调）且无类型检查覆盖 |

## 6. 硬规则（R1–R6）

**R1 证据先行。** 问题与结论一律附 `文件:行号` 或命令输出；文件清单、消费方、行号在批前实时 `grep` 当前工作区，不信旧快照。

**R2 机制先于搬移。** 搬移只用于切断重依赖边（S5）、建立单一事实源（S4）、按域拆分（S7），不为美观搬移。

**R3 小批交付与分级容量。** 每批独立可提交、可验证；T1 与 T2b / T3 不混批（确需混批按最高类型验证）。批次容量：
- **T1 / T2a / 有静态类型兜底的 T4**：同一子域可含多个改动点，上限 ≤20–30 个关联文件，以用户一次能审完为准。
- **T2b / T3**：每批聚焦 1 个主文件或 1 组重复逻辑。

**R4 行为变化即停（测试只读冻结）。**
- **通用触点**（各语言特化表现见 `references/lang-<stack>.md` §3）：
  1. 动态加载、反射调用、宏展开、动态键名拼接。
  2. 顶层副作用导入、DI 自动扫描注册、环依赖（删转口或改名可能改变初始化/注册顺序）。
  3. 跨边界字符串契约（模板绑定、事件名、序列化/持久化键、ORM 映射、i18n 键）。
- **唯一判定与处置定义**：既有测试断言与基线在重构期间**严禁修改**（测试改动绝不与重构混交）；一旦需改断言或基线才能通过，即判定行为已变——**立即停止并回滚本批 commit，移入不做清单或交用户裁决**。

**R5 不做清单与优化清单同权重。** 逐条写明理由类型（见 `playbook.md`）与重评触发条件。

**R6 结果须可审查、可修改。**
- 每个新文件、新目录能用一句话说明职责，且必须通过“浅模块删除测试”（若删掉该模块后调用方复杂度未变，仅为透传拼装，则属浅模块，不拆）。
- 严禁为卡行数而按行号机械截断逻辑（如拆出无独立语义的 `part1/part2`）。
- **批内同质与 commit 规范**：全仓机械改写（S1/S6）不与文件拆分（S7）混批；T1 / T2a / T4 每批单 commit，T2b 搬移夹杂修改时拆为“纯搬移”与“引用改写及修改”两个 commit；每批审查摘要（改了什么、先看哪些文件、需人判断的点、验证结果）写入 commit message 正文。
- 与检索效率冲突时，优先检索效率，但把取舍写进 commit message 审查摘要交用户判断。
