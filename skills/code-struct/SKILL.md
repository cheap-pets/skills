# 代码结构规范（编写阶段）



## 1. 判据与边界

写出的结构须让 agent **只用静态手段**（模块导入关系、函数/类型签名、`grep`、`wc -l`）就能回答：① 这个功能在哪？② 改这里影响谁？

- **优先级**：agent 读取、分析与修改效率 > 人类审查成本 > 主观美观。
- **约定优先**：项目、语言与框架的既有约定（目录、分层、命名、标准机制与上游契约签名）优先于本规范默认值。
- **作用边界**：只约束本次新增或触达的代码，不顺手重构无关存量（存量重构交由 `/code-restruct`，注释规范交由 `code-comments`）；触达代码中暴露的超标参数可顺带收敛，命名冲突在本次范围内解决。遇到既有环依赖、历史同源重复等存量问题，不扩大债务，一句话提示用户。单点微改动（修单行 bug、改文案/样式/配置值、几行以内的局部调整，且不涉及新文件、新导出或新依赖）直接修改，免执行前后扫描与自检。



## 2. 动手前：按需定位（先搜再写）

涉及新建文件、新增跨文件导出或新增通用逻辑时：

1. `grep` 领域关键词，确认是否已有同源实现、同名符号或现成落点；有则复用或扩展，不另造。
2. 按业务域选落点；同一需求的核心逻辑通常集中在 **1–3 个高内聚文件**。
3. 新建文件/目录前，先用一句话说出其独立职责；说不出则并入既有模块。



## 3. 文件规模与拆分

| 触及文件情形 | 做法 |
| :--- | :--- |
| **新建文件** | 目标 `≤350` 行 |
| **改后 400–600 行** | 单一职责且内聚可继续写入；若已含多职责且本次新增的是独立新职责块，另起新文件 |
| **已 >600 行（硬线）** | 独立新特性/新职责块放新文件并引用；原职责内的紧耦合小修补允许原位修改，完成后一句话提示“该文件超 600 行，建议后续运行 `/code-restruct`” |
| **豁免** | 纯 schema / 静态配置表 / 单一状态机 / 生成代码；含模板、样式或内联测试的文件按核心逻辑块行数计 |

- **拆分次序**：先把无副作用的纯函数、常量、类型定义放独立文件；有状态逻辑控制在最小范围。
- **防过度碎裂**：400–600 行的高内聚单职责文件不拆；新模块须通过“浅模块删除测试”（删掉后调用方复杂度没变、只是透传拼装，则不建）；不拆透传参数/事件的薄封装；不按行号机械截断（如 `part1/part2`）。
- **可命中命名**：承载业务逻辑的文件名与导出名带领域关键词，使按功能词 `grep` 即可命中；不把核心业务塞进 `utils` / `common` / `helpers` / `misc` 万能桶。



## 4. 依赖方向

- **单向向下**：基础/纯逻辑层 ← 业务领域层 ← 界面/接口入口层；下层不引用上层。
- **不新增环依赖**：两模块需互引时，把共享的纯函数或基础类型下沉到更底层的独立模块；不靠延迟/局部导入绕开真实业务环（仅静态类型检查导入或重型库按需加载除外）。
- **不新增有害转口**：不建二跳以上嵌套转发或易致环的内部纯转口聚合文件，消费方直引实现文件（包根对外标准入口除外）。
- **克制导入副作用**：普通业务与工具模块被导入时不隐式执行 IO、网络请求或全局状态改动（框架声明式注册除外）。



## 5. 签名即契约与命名

- **显式签名**：跨文件导出的函数、方法、数据结构须有显式类型签名（入参与返回值），使 agent 读签名即可安全调用，无需展开读实现体。
- **跨文件语义唯一**：跨文件可见的导出符号、共享状态字段、对外参数/事件名同名即同义，不用 `data` / `info` / `item` / `list` / `value` / `res` / `obj` 等泛化名承载模糊含义；局部变量与语言/框架惯用名不受限。
- **变更闭环**：改共享符号（名字或签名）前先 `grep` 消费方，同批改完，不留新旧并存。



## 6. 单一事实源

- 同一业务规则、核心常量、领域类型只在一处定义，其余处引用；不写“与 X 保持同步”式的复制代码。
- **不过度抽象**：局部显式样板、无演进耦合的相似代码可保留；不为强行合并略有差异的代码引入布尔旗标或大量条件分支。



## 7. 参数形态与隐式依赖

- **参数收敛**：位置参数 `>5`，或 `≥3` 且含布尔旗标 / 同类型相邻参数 / 空值占位 / 连续透传 `≥2` 层时，改用强类型 options/params 对象或命名参数；能拆成两个职责清晰函数的，不用布尔旗标切换行为。
  - 上游契约锁定的签名（框架回调、接口或基类实现、包外公共 API）不单方改签名。
  - 不退化为无类型的通用容器参数袋。
- **少用隐式边**：少用跨文件可变的全局状态与松散参数袋，必须共享时把状态写入收敛到单一入口（显式方法/action）。
- **可静态追踪**：不用动态拼接键名或反射替代能静态引用的调用；跨多文件复用的事件名、存储键等字符串契约集中定义为常量或枚举。



## 8. 完成前快速自检

对本次**新建文件、新增或改名跨文件导出、大块追加代码**的文件快速核对（单点微改动免检）：

- 每个新文件能一句话说明独立职责，且行数按 §3 口径计 `≤350`；触及的存量文件未违规突破 `400 / 600` 线。
- 新增导入方向向下、无环、无新增内部纯转口。
- 新增/改名的跨文件导出符号已 `grep` 无同名冲突，且有显式类型签名。
- 无复制粘贴的同源业务逻辑；新增函数参数形态合规。

有被迫违反或权衡取舍的项，在交付说明中一句话写明原因。
