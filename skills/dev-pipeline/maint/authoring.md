# 编写指南（维护文档，不进入运行时加载图）

> **冻结扩展声明**：四条内置流水线（`dev` / `design-review` / `impl-verify` / `bugfix-verify`）处于稳定收敛期，半年内（至 2027-05）暂不新增角色与流水线。确有 ≥3 条新流水线需求时，先评估「stage 契约 + 声明式转移表」引擎化方案后再解冻。

## 1. 新增角色契约规范

1. 在 `agents/<角色文件名>.md` 中创建契约文件。契约**不含 YAML frontmatter**（模型绑定收敛到 `slots/`），以正文标题开头：

```markdown
# <角色>契约

你是<角色>。<一句话职责边界>。

## 规则
- 输入、输出路径以派发为准；确认 `00-task.md` 含必需项（<列明>）。先读 `decisions.md`（若有）：视为已确认约束，冲突时指出，不得写入。
- 只写指定输出文件；<Bash 与源码边界>。
- 每条结论附证据（`path:line`、命令输出）；无证据标“推测”或 `UNVERIFIED`。

## 输出文件结构
（首行带 `VERDICT: <值>` 或 `STATUS: <值>`；改源码类开工写 `进行中` 占位值以支持断点接续；只读评审 / 验证类开工写 `未定` 占位以支持中断恢复；探索类整份报告单次 Write 落盘，缺失即未完成）

## 返回（≤N 行）
```

2. 在 `roles.md` 注册表与模式矩阵中登记：段号取当前最大段号 + 1；评审与验证类角色必须在「独立于」列标明被独立方。
3. **宿主安装同步**：新增或修改 `slots/*.md` 或 `agents/*.md` 后，由实际运行的宿主（harness）重新运行 `node <skill 目录>/scripts/pipeline-ctl.mjs install --target <宿主的 subagents 定义目录>`，将 3 个槽位复制到 subagents 定义目录。修改槽位承接角色时，同步更新 `slots/*.md` 的 `description` 角色映射与 `roles.md`「默认槽位（回退）」列（两处为同一映射的两个视图）。
4. **槽位模板规范**（`slots/pipeline-<slot>.md`，仅 `primary` / `peer` / `executor` 三档）：frontmatter 必填 `name`（与文件名一致）、`description`（角色映射 + 仅由调度者指派）、`model`（primary / peer 为 `opus`，executor 为 `sonnet`；peer 需切异构评审模型时只改此字段）、`tools`（peer 不含 `Edit`，其余含）。正文固定四条：先读派发首行契约并严格遵守；未收到契约路径或不可读 → 不执行，返回「未收到契约」；超出契约写入边界的工具严禁使用（peer 直接声明无 Edit）；不得派生子智能体。

## 2. 编写流水线规范

每条流水线文件 `pipelines/<id>.md` 必须采用统一的**自包含二维状态转移表**结构，禁止使用跨多文件跳转的“通用骨架 + 差异覆盖”写法（组合流水线可引用子流水线入口，仅一层，且不得覆盖子流水线内部转移）：

```markdown
# 流水线：<名称>（<id>）
<一行：阶段链>

## 前置（目录初始化、00-task.md 必填项、启动确认窗口）

## 阶段与状态转移表
| 阶段 | 角色（默认槽位） | 读 | 写 | 返回值 / 事件 → 下一步动作 | 计数键与上限 | 耗尽去向 |

## 路由细则 / 检查点（如有）

## 结束（汇报补充项）
```

## 3. 静态一致性自检（Lint）

每次修改协议文件后，必须运行：

```bash
node <skill 目录>/scripts/pipeline-ctl.mjs lint
```

确保所有必需文件存在（含 `slots/`×3）、槽位 frontmatter 合规、契约无 frontmatter、且无已废弃的旧状态引用。随后按 `maint/dry-run.md` 执行核心场景的状态机推演。
