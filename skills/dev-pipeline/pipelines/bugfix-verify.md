# 流水线：缺陷修复（bugfix-verify）

定位（B1）→ 修复方案（B2）→ 实施（I1）→ 验证（I2）。全程单片整体执行，不设无设计直修。

## 前置

按 `references/start.md` 执行（需问用户的项合并为**一次**提问）：
1. 运行 `node <skill 目录>/scripts/pipeline-ctl.mjs init <task_dir>` 建立任务目录与 `00-baseline.txt`。
2. 若用户提供了报错堆栈或长复现日志，原文不改写存入 `.pipeline/<task>/00-repro.txt`。
3. 编写 `00-task.md`（≤60 行）：
   - **目标**：缺陷现象、复现步骤、期望行为、环境 / 版本、以及 `00-repro.txt` 路径指针（或仓库内日志位置）。若复现信息不足以定位，先向用户追问。
   - **验收标准**：① 按复现步骤操作，缺陷现象消失且符合期望行为；② **新增回归验证覆盖该缺陷**（优先自动化回归测试；确属纯声明式/视觉配置或环境受限无法端到端复现时，写覆盖根因逻辑分支的单元测试或标明 `HTTP` / `浏览器` / `人工` 复现步骤）；③ 验证命令全绿。
   - **策略参数**：`on_design_blocked: return_to_plan`，实施粒度固定为 `整体`。
4. 开启 `references/start.md`「启动确认窗口」，确认后进入 B1。
5. 根因已明（用户给出定位结论，或 `00-repro.txt` 已含根因）时，B1 跳过或仅快速核对即进 B2；B2 回归先行约束不变。

|---|---|---|---|---|---|---|
| **B1 定位** | explorer（`primary`） | `00-task.md`, `00-repro.txt`（如有）, `decisions.md` | `01-explore.md` | 派发追加约束：`任务是定位缺陷；相关代码首列触发路径与疑似根因（path:line），未确证的标“推测”并在未解问题写明所需验证`<br>- `决策冲突 > 0` 或 `未解问题 > 0`（需用户补充复现信息） → 停下询问用户，记入 `decisions.md` / `00-repro.txt`<br>- 正常返回 → 进 **B2 修复方案** | — | — |

## 回归先行规则（B2 设计与 I1 实施共同遵守）

1. **第一步（先证伪/复现失败）**：
   - 优先编写自动化回归测试并运行，确认其在修复代码前**因该缺陷而失败（Red）**。
   - **偶发竞态或环境受限豁免**：若缺陷为偶发竞态（Flaky），或端到端复现依赖浏览器 / 外部环境而当前执行环境受限，改为编写**直接覆盖根因逻辑分支的单元测试**并确认该单元测试在修复前失败；若缺陷纯属静态文案 / 样式 / 声明式配置且无逻辑分支可测，在测试计划标为 `人工` 并在实施记录注明跳过原因。
   - 除上述 `人工` 豁免外，若回归测试或复现步骤在修复前已直接通过，说明 B1/B2 的根因假设不成立，`implementer` 必须**立即停止**，在「偏离」节记录运行输出并返回 `STATUS: BLOCKED(设计事实有误)`，严禁继续修改业务代码。
2. **第二步（实施修复）**：按 `02-design.md` 修改源码，使上述回归测试通过（Green）。
3. **第三步（全量自检）**：运行 `00-task.md` 中的验证命令。

## 回方案流程（I1 触发 `return_to_plan` 时）

1. 运行 `node <skill 目录>/scripts/pipeline-ctl.mjs status <task_dir>` 获取当前 `return_to_plan_j`。
2. 若 `return_to_plan_j >= 回头上限` → 停下向用户汇报已查明的事实、偏离原因与产物路径，给出耗尽三项选择（见 `references/comms.md`）。
3. 未达上限 → 在 `decisions.md` 追加一行 `- [回方案 <j+1>] <原根因假设被推翻的证据或偏离原因>`。
4. 派发 `explorer`（`primary` 槽位）重定位：输入含 `00-task.md`、`00-repro.txt`、已有 `01-explore*.md` 及刚产出的 `04-impl*.md`「偏离」节，输出 `01-explore-回-<j+1>.md`（不占补探索额度）。
5. 派发 `designer / 修订`（`primary` 槽位）：读取 `04-impl*.md`「偏离」与 `01-explore-回-<j+1>.md`，更新 `02-design.md` 的根因、修复点与 `## 偏离处理`。
6. 以 `implementer / 续做` 模式重进 I1（读取全部 `04*` 与更新后的 `02-design.md`，输出 `04-impl-整体-续-<j+1>.md`）。

## 结束

按 `references/comms.md`「结束汇报」模板输出，首行额外附**根因一句话总结**与回方案次数。
