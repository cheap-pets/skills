# Design Razor

**最小充分复杂度：满足目标和硬约束即可。** 已有方案是默认基线，变更需要依据。评审的成功标准是准确判断是否存在值得处理的问题；结论可以是「无需修改」。

## 1. 使用方式

- **自己评审**：按 §3 执行，评审者同时完成裁决，每轮读取并更新决策记录。
- **下发其他模型 / 子智能体**：默认只传设计基线（含决策记录）、评审范围与当前级别准入范围，不复制完整指令（除非确认对方可读，否则不单发路径），并至少明确：
  - 只报符合准入范围、有具体触发场景的实质性问题；
  - 已决、已拒绝、暂缓事项无新证据、条件变化或原判断错误不得重提；
  - 待验证事项按原记录跟踪（有验证结果、条件变化或原判断错误时更新），不重复作为新问题提出；
  - 不重写或扩展方案，不凑数；无问题则报「无准入问题」。
  - 需对方独立执行完整评审与裁决时，再复制 §3 指令。
- **评审与裁决分离**：裁决者以评审意见为输入，合并相近意见（意见数与模型数不作采纳依据），按 §3【裁决】与【输出】执行。
- **统一基线**：所有 Agent 基于同一份方案和决策记录，不各自建立基线。

## 2. 设计边界、决策记录与级别

### 方案头部

开始前写入方案文档头部（无文档则在对话中维护；已有则沿用，不每轮重建）：

```markdown
## 设计边界
- 目标 / 成功标准：
- 硬约束（仅限用户或需求明确陈述）：
- 非目标：
- 收敛级别：standard | robust

## 决策记录
- [已决] 内容 — 理由
- [暂缓] 内容 — 已确认的触发路径；不处理的理由
- [待验证] 内容 — 待确认的事实；结果如何影响决策
- [已拒绝] 内容 — 理由
```

- 决策记录只留影响后续决策、边界或可能被重提的事项，不记一般建议。
- 硬约束不受级别限制，评审者不自行推断硬约束。
- 不自行扩大需求，不把未知条件当作必须防范的风险，不为未明确的未来需求预留设计。

### 收敛级别

| 级别 | 适用 | 准入范围 |
| :--- | :--- | :--- |
| `standard` | 默认 | 违反硬约束、阻塞核心目标或损坏数据的问题；高频主路径上的明确缺陷。关键边界做必要校验并清晰报错；不为低频边缘情况加防御分支或复杂状态机 |
| `robust` | 用户指定，或方案涉及资金、权限、核心基础设施，或数据损坏后难以恢复 | 以上 + 有具体触发路径且后果严重的低频问题（静默数据损坏、越权、关键状态不一致）。允许按需采用重试、幂等、降级、补偿等机制，但每项须对应具体触发路径和失效模式 |

- 用户可进一步限定本轮评审范围；评审范围内，已纳入基线的硬约束仍属准入条件。若用户明确排除某部分，应标明该部分未评审，不得视为已验证。
- 级别写入头部后固定；仅在目标、环境或风险后果发生实质变化时重评并说明依据，不得为容纳某条意见而升级。

## 3. 评审者指令

```text
你是方案评审者，负责评审并对自己提出的意见做出裁决。任务是验证方案是否满足目标和约束，不是尽可能多地找问题；不要把所有建议合并进方案。

【基线】
- 目标与成功标准：{内容}
- 硬约束：{内容}
- 非目标：{内容}
- 决策记录：{内容或可读取的位置}
- 评审范围：{全文 | 指定章节 | 仅本轮变更}
- 准入范围：{当前级别一行}
- 其他评审意见（如有）：{内容}

【评审】
1. 已决、已拒绝、暂缓事项，无新证据、条件变化或原判断错误不得重提；待验证事项按原记录跟踪，有验证结果、条件变化或原判断错误时更新，不重复作为新问题提出。
2. 每条准入问题写明：对应的目标/硬约束；具体触发场景与条件；影响与可能性（定性，说明依据，不编造概率）；现设计为何处理不了；最小修复。
3. 理论可能性、个人偏好、追求完整性的建议、无具体场景的猜测，不提。
4. 其他评审意见与自己的意见一并处理：相近意见合并；意见数量、模型数量、表面一致不是采纳依据。
5. 评审范围为「仅本轮变更」时：只检查变更是否正确落地、是否引入新问题或破坏既有目标和约束；沿用原级别，不重审未变更部分。
6. 没有准入问题就不提，不因身份或轮次凑数。

【裁决】
对每条意见独立判定。判定前先反驳自己：现设计是否已合理处理？
- 采纳：符合准入，或明确违反硬约束。
- 暂缓：已基本确认，但超出准入范围或属非目标。
- 待验证：触发路径具体，关键事实未知且结果可能改变决策；写明验证事项及对决策的影响。
- 拒绝：缺场景或依据、影响不足、属偏好，或现设计已合理处理。

采纳约束：
- 收益须明显高于成本（实现、维护、运维、性能、依赖、认知）；违反硬约束的必须修复，成本只用于选择修复方式。
- 选最简修复，不重复建设已有机制。
- 可删除评审范围内有明确依据的冗余设计，不借此扩大评审范围；不新增与已确认问题无关的机制。

【输出】
- 裁决结果：每条给出状态和一行理由；没有意见则写「无准入问题」。
- 方案变更：只输出修改部分，或「无需修改」。
- 决策记录：仅列新增或更新的条目；暂缓、待验证仅在值得保留时记录。
```

## 4. 迭代与停止

- **默认节奏**：一轮评审 + 一轮复核（复核时评审范围填「仅本轮变更」，沿用原级别）。
- **继续条件**：存在新需求、新证据、关键假设变化或重大设计调整；仍有可优化之处不构成理由。
- **停止条件**（满足以下条件即停止，并保留必要的暂缓事项）：
  - 本轮评审范围内的目标和硬约束已满足，当前级别内无未解决的准入问题（影响核心目标或硬约束的待验证事项视为未解决）。
  - 剩余问题的影响不足以抵消解决成本。
