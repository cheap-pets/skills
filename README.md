## Skills 简介

### dev-pipeline

子智能体协作开发技能——指挥多个子智能体完成一次对话装不下的开发任务。

适用：跨模块功能、重构、公共接口变更、复杂缺陷定位修复。
触发：仅当用户点名流水线 / 子智能体 / 多 agent 协作时启用。

**安装子智能体**——3 个槽位子智能体需复制到宿主的 subagents 定义目录：

- 来源：`skills/dev-pipeline/slots/`
- 槽位：`pipeline-primary` / `pipeline-peer` / `pipeline-executor`
- 无需手动操作：可直接让 agent 安装，或首次使用检测不到时，agent 会提示并安装
- 也可手动复制：将 `slots/*.md` 复制到宿主的 subagents 定义目录（如 Claude Code 为 `.claude/agents/`）

安装命令（agent 执行，供参考）：

```bash
node skills/dev-pipeline/scripts/pipeline-ctl.mjs install --target <宿主的 subagents 定义目录>
```

- **dev**：无设计要实施——探索 → 设计 + 评审 → 确认门 → 实施 + 验证。
- **design-review**：只要方案并过审——设计 → 独立评审 → 修订。
- **impl-verify**：已有确认的设计——实施 → 范围核对 → 独立验证 → 修复。
- **bugfix-verify**：缺陷根因未明——定位 → 修复方案 → 修复 + 验证。
- **单点 / 临时组合**：也可只点名单个角色，或点名多个角色按依赖顺序协作。



### code-layout

代码纵向排版规范技能——用空行按意图分段、规范引入语句顺序。

适用：新写、大段改写或重构代码；单行小改不需要。
触发：写码时自动激活；用户提到排版、分段、空行、整理引入语句、"代码太挤"时也触发。

- 只管空行分段与引入语句排序；符号、缩进、引号、行宽交给 linter/formatter，项目已强制的规则优先。
- 引入语句按「标准库 / 外部依赖 / 项目内部」分组排序；JS/TS/Vue 新建或整体重构时运行脚本自动排序。
- 默认只调整本次编写或修改的代码，不顺手重排无关行；用户要求批量重排时例外。



### code-struct

编写阶段的代码结构规范技能——让 Agent 日常写代码时就产出结构良好的代码，从源头遏制结构腐化。

适用：新建文件、追加逻辑、设计签名、增改参数、引入依赖、复用抽取等日常写码场景。
触发：写代码时常驻自动激活；单点微改动免扫描免自检。

- 单文件 8 节，按「边界分流 → 动手前 → 写作中 → 完成前」生命周期组织。
- 核心判据：仅凭静态手段（导入关系、签名、`grep`、`wc -l`）能回答「功能在哪、改这里影响谁」。
- 与 code-restruct 分工：本技能事前预防（只管新增/触达的代码），`/code-restruct` 事后治理存量。



### code-comments

代码注释规范技能——约束实现注释、API 文档、docstring、TODO 及 lint / 类型检查抑制说明的增删与维护。

适用：代码生成、修改、重构和评审任务。
触发：写/改/审代码时自动激活；触发不代表必须新增注释。

- 两条主规则：删掉注释不熟悉的读者会做错事才写（取舍）；注释原因必须有依据，不编造。
- 先改进代码（命名、提取函数、类型），不用注释复述实现或掩盖设计问题。
- 改代码时同步维护受影响注释，过期注释视同缺陷；评审只挑错误/过期/误导注释，不挑风格。



### code-restruct

行为不变的结构重构技能——提升 Agent 读取、分析、修改代码的效率，兼顾人类低成本审查。

适用：依赖梳理、拆分大文件、跨文件同名消歧、清理有害转口、合并同源重复、收敛参数形态。
触发：仅手动调用 `/code-restruct <模块路径>`；未给路径时先询问目标模块。

- 支持 JS/TS/Vue、Python、C#、Rust 四类语言分册，其余语言先确认参照分册。
- 4 步工作流：快速诊断（含早退门禁）→ 轻量规划 → 分批执行与即时验证 → 收尾；≤5 个文件改动零中间文档。
- 验证默认去探针化：编译/类型检查 + 既有测试（只读冻结）+ 残留扫描，行为变化即停。



### just-enough

方案收敛与评审技能——防止过度设计、防御性堆料，保持最小充分复杂度：满足目标和硬约束即可。

适用：制定、评审或迭代技术方案，尤其多模型或子智能体协作评审。
触发：方案制定 / 评审 / 迭代时使用。

- 方案头部维护设计边界（目标、硬约束、非目标）与决策记录（已决 / 暂缓 / 待验证 / 已拒绝），已决事项无新证据不得重提。
- 收敛级别 `standard` / `robust` 决定问题准入范围；级别一经固定，不为容纳意见而升级。
- 评审者指令内置于 skill：可自己评审，也可下发子智能体（只传基线与准入范围，不复制完整指令），评审与裁决分离。
- 明确迭代节奏与停止条件：默认一轮评审 + 一轮复核，目标与硬约束满足且无准入问题即停。



### outsource

调度者模式技能——激活后主智能体只做任务分派，把小功能、缺陷修复、调研、验证等规模不大的工作外包给子智能体。

适用：一个会话内多次有关联的碎片化任务；单个任务以子智能体一次上下文可完成为限，过大则拆分。
触发：仅手动激活（用户点名 outsource / 外包 / 调度模式）；未点名不启用。

- 会话级目录 `.outsource/` 沉淀任务简报、进度、总结与可复用代码知识（含踩坑），任务间经知识文件与前置任务衔接，后续关联任务直接复用，中断后可接续。
- 主会话保持克制：调度者不读源码、设计文档与配置，输入经 brief 路径传递，不进主会话上下文。
- 沿用 dev-pipeline 的 `pipeline-{primary,peer,executor}` 槽位子智能体；git 快照越权核对，改动必须落在 brief 范围内。
- 需要设计评审、独立验证门禁、跨模块重构或公共接口变更时，建议改用 dev-pipeline（可并用）。
